# Chrome Extension & bridge.js

`bridge.js` is the single content-side entry point shared by headless mode (Rust registers it via `Page.addScriptToEvaluateOnNewDocument` with a `worldName`) and browser mode (manifest content script).

## World placement
- Both modes run the bridge in an **ISOLATED** world — browser as a manifest content script, headless in the CDP isolated world `webpilot_bridge` that auto-loads on every document. Its globals (`__webpilot_handle`, `__webpilot_state`, the index snapshot, `uploadTarget`) are unreachable from page JS in either mode, so a hostile page can tamper with the DOM it *presents* but cannot replace the stored snapshot references. Live DOM changes can still
  alter an action's effect; snapshot validation is not application-level authorization.
- `content/bridge.js`, `content/dialogs.js` and `content/monitor-console.js` / `content/monitor-network.js` are the page-side scripts both modes run: the extension injects them by path, the Rust crate embeds the same files with `include_str!`. A change to what they do therefore cannot land in one mode and miss the other.
- Page expressions (`eval`, `frame find`) and the console/network monitors deliberately stay in the **MAIN** world: the first must see page globals, and the monitors hook the *page's* `console`/`fetch`, which an isolated world would never observe. Headless routes each bridge call to the frame's `webpilot_bridge` context and each page expression to its default context; browser resolves the same split via `resolveFrameWorld`.
  - **Monitors are best-effort, not tamper-proof.** The hooks and their buffer live in the MAIN world, so a page can evade them or write entries of its own, an `exception`-tagged one included. Both read paths validate the shape; nothing in the MAIN world can authenticate provenance. The recorder stamps the contract it satisfies (`__webpilot_<kind>_shape`), and a read fails loud on another build's recorder rather than reading it as a quiet page. Neither an empty buffer proves the page did nothing nor a filled one that it did.
  - **The console monitor records what the page reports**: `console.*` calls, `window`'s `error` and `unhandledrejection` (typed `exception` / `rejection`, in the browser's own words), and a failed `console.assert`. `console.trace`/`table`/`dir`/`group` are not hooked, nor is a failed subresource load, whose element-level `error` names no reason. An entry is committed once the dispatch is over and only if the page did not cancel the event; why that takes a port message: the comment above it in `monitor-console.js`.
  - **Where a monitor starts recording differs per mode.** Headless registers the hooks per document with `Page.addScriptToEvaluateOnNewDocument`, ahead of the page's own scripts. Browser mode injects at navigation settle: a document-start MAIN-world injection would need a URL-matched content script, which reaches every tab the user browses, or a session-long debugger attach, which keeps Chrome's debugging banner up. Neither mode observes a document built while nothing was attached (between two CLI invocations, or a popup already loading when it appears); `webpilot mcp` holds its session, so the first is covered there. Every read reports which it got as `covers_load`, stamped from the null `documentElement` only a document-start injection sees, so a missed load never reads as a quiet page.

## Accessibility bundle
- `extension/vendor/semantics.js` is generated from pinned `dom-accessibility-api` and `aria-query` dependencies; `npm run lint` checks that the bundle and its licenses match their sources. Both modes load it before `bridge.js`. Edit the build script or dependencies, not the generated bundle. These DOM calculations are not a complete browser accessibility tree; use `capture --include accessibility` when that tree is needed.

## Public binding
- `window.__webpilot_handle(msg)` — sole exported function. Returns a value or a Promise. Namespaced to avoid colliding with page globals.

## Wire shapes
- **Messages** are `type`-tagged bridge requests, such as `{ type: "executeAction", action, snapshot_id }` and `{ type: "wait", condition, timeout_ms, request_id }`. The nested `action` and `condition` keep the serde shapes of `crates/webpilot`: `kind` is the snake_case `ActionKind` (`action.rs`), `until` tags the `WaitCondition` (`wait.rs`). A scoped `cancelWait { request_id }` removes that wait's observer/timers without touching other waits.
- **Errors**: `{ success: false, error: { code, message, ...data } }` where `code` matches `WebPilotError` variant (e.g., `ElementNotFound`, `StaleSnapshot`, `SelectorNotFound`, `Timeout`) and `...data` carries the Rust variant fields (`requested`, `available`, `index`, `selector`, `kind`, `elapsed_ms`, ...).
- **Frames**: switching is **not** a bridge message — headless drives CDP
  directly (`do_frame_switch`), browser uses the service worker
  (`handleFrameSwitch`). The bridge has no `switchFrame` case.

## Index resolution (snapshot-bound)
- `extractDom` stores the picked element references in `state.snapshot` (index order). Index-addressed messages (`executeAction`, `prepareClick`, `getElementCoords`, `prepareUpload`) resolve against that stored list via `resolveIndex`, so an index always targets the element the agent saw at capture time — never a freshly-collected element that may have shifted. `upload` is the one action that must hand a node to CDP (file inputs can't be filled by JS): `prepareUpload` stashes the resolved snapshot element on `state.uploadTarget` by **object identity**, and CDP resolves that stored reference (in the bridge's isolated world, both modes) to an `objectId` and sets the file on that object. There is no marker attribute and no document-order re-query, so a page can neither observe nor redirect the target between resolve and sink — and the direct object reaches a file input inside an **open shadow root**, which a document-root selector lookup cannot.
- Indexed commands carry the observed `snapshot_id`. The bridge rejects a mismatched one and revalidates the stored node against the `StaleSnapshot` contract in the root `CLAUDE.md` (liveness, visibility, the captured semantic properties). Values and selection state may change without changing element identity.
- `click` resolves the captured node, chooses a hit-testable `getClientRects()` fragment and maps it to the same CDP content-quad index. It checks geometry and hit targets again after pointer movement before pressing; wrapped links must never use their union bounding-box centre. Pointer hit testing uses document coordinates; input dispatch uses viewport coordinates. Parent-frame overlays are checked through the hit test's frame id, and each cross-site `<iframe>` on the way up through its owner element.
- Dialogs: `content/dialogs.js` (MAIN world, both modes) answers alert/confirm/prompt in the page and records each in `window.__webpilot_dialogs`, so no dialog holds the page — not even one raised after a CLI command detached. Headless registers it per document with `addScriptToEvaluateOnNewDocument`; browser mode injects it into the pinned tab's documents at commit and before each action. The answer is `chrome.accept_dialogs`, or OK for the one action that passes `accept_dialogs`. Each action and capture takes the records (`take_dialogs` / `takeDialogs`, shape-checked, since the page can write the global) and reports them. Headless's CDP responder answers what still reaches the browser — a beforeunload, or a dialog in a document without the handler — by the same answer into the same record; a navigation whose beforeunload it answered Stay fails `NavigationFailed`, after the responder has answered, since an unanswered dialog left by an exiting process holds the page. Browser mode leaves beforeunload to Chrome, which shows it to the user.

## Interactivity and visibility
- Interactive set = the semantic allowlist (`a[href]`, `button`, inputs, ARIA roles, `contenteditable`, `details>summary`) ∪ explicit click markers (`onclick`, `jsaction`, framework `@click`/`data-action`, and `tabindex >= 0` only — `tabindex=-1` is script-only focus, not an affordance) ∪ the **innermost** `cursor:pointer` element (one that wraps no already-collected interactive node, so a clickable card doesn't shadow its real button). The semantic allowlist has no size gate (a real `<button>` is interactive at any size); the heuristic passes (markers, `cursor:pointer`) drop degenerate sub-5px rects (tracking pixels). Visibility gates extraction except for file inputs, which remain indexed while hidden for CDP upload.
- Shadow-DOM coverage: the semantic, marker and tabindex candidates are collected in one open-shadow-root walk (`queryAllDeepMulti`) under a shared `SHADOW_HOST_BUDGET`, so a web component whose clickable part lives in its shadow root is captured. The `cursor:pointer` pass is light-DOM only — `Node.contains` does not cross shadow boundaries, so its innermost/wrapping computation is undefined there; a pointer-styled element carrying no marker/role/semantic tag inside a shadow root (exotic) is the one uncovered case.
- `isVisible` is the one visibility predicate for extraction and action-time revalidation, so the two cannot drift; why it calls bare `checkVisibility()` and walks `opacity` up the ancestors: the comment above it in `bridge.js`.

## New-element semantics
- `is_new` is detected by **node identity**: an element is new when its reference was absent from the previous snapshot (`state.snapshot`). Identity is collision-free and survives re-renders that keep the node (a framework that *replaces* nodes will mark replacements new — that is the identity model's honest trade against content-hash collisions). With no usable baseline — the first capture in a document — nothing is flagged: a fresh page is not "all new". Same-document hash and SPA URL changes keep the baseline; newly added nodes are still marked. There is no content-hash key.

## Versioning
- Every NM `Ping` (connect-time hello + keepalive) carries `extension_version` from the manifest, so the host can detect a stale install and reject commands with `VersionMismatch`.

## Listener attachment
- The `chrome.runtime.onMessage` listener is removed and re-added on every injection, so SPA bfcache/restore cycles cannot leave a stale listener.

## Limits
- Every page-controlled display field is clipped at extraction — the per-field caps are the `clip(value, N)` calls in bridge.js (element text the largest cap, ids/roles the smallest). Option `value` is the one deliberate exception (NOT clipped — `action select` matches the exact live value). Shadow-DOM traversal is bounded by a shadow-host budget (not a depth cap), warning when it clips.
- All truncation is codepoint-safe (`clip()`): it never splits a UTF-16 surrogate pair, so a clipped astral character can't emit a lone surrogate that would break the snapshot's JSON serialization.
- `keyDescriptor()` (browser) / `key_descriptor` (headless) maps Enter / Tab / Escape / Backspace / Delete / Arrow* / Home / End / PageUp / PageDown / Space / Insert / CapsLock / F1-F12.

## Service worker (browser mode)
- The worker is an **ES-module graph** (`manifest background.type: "module"`) whose domain modules mirror the Rust transport files one-to-one — `action`/`capture`/`query`/`state`/`browser`.js ↔ the same-named `transport/local/*.rs` — plus infra modules `errors`/`session` (pins, monitor sets, host config, persistence)/`cdp`/`content` (bridge link)/`navigation`/`router` (the `LocalTransport::send` twin)/`host` (NM link). `service-worker.js` is the entry: persistent `chrome.*` event listeners are registered there synchronously at startup, so MV3 can wake the worker for their events. Request-scoped listeners are registered by the operation and removed during cleanup. Two deliberate cycles, each a hoisted function declaration accessed only at call time, which ESM defines as safe: `browser.js` imports `isHostConnected` from `host.js` (host→router→browser→host), and `session.js` imports `rearmMonitors` from `state.js`, because a read's borrow moves the pin.
- `nmPort?.postMessage()` for NM communication (optional chaining handles SW restart races).
- `handleStatus()` returns `connected: !!nmPort` — derived from real port state — and reports the pinned tab and its `pin` state without ever pinning as a side effect.
- `withCdp(tabId, fn)` serialises concurrent CDP operations per tab; the per-tab `cdpLocks` are pruned on `tabs.onRemoved`. The armed-monitor intent is **agent-level** (one flag per kind, the headless model), re-injected on the pinned tab at every pin move and navigation settle — it survives the pinned tab closing.
- **Active tab**: every command targets one pinned tab, persisted in `storage.session` across SW restarts with whether it was borrowed. A handler that only reads resolves it with `resolveTabForRead()`, which borrows the tab the user is viewing while nothing is pinned; every other handler uses `resolveActiveTab()`, which refuses with `NoPinnedTab` instead, so an effect never lands on a page the agent has neither opened nor observed. Loading a URL (`navigateBoundTab`, behind `navigate`, `capture --url` and `tab new`, which always opens one) opens a tab of its own unless the pin is the agent's own; every other command, `reload` and `back` included, acts on the pinned tab whoever owns it. Once set, the pin moves only by `tab switch` / `tab new` / a tab a navigation or click opened, `tab close` on it releases it, and a command that opened a tab and failed restores the previous pin (`currentPin` / `restorePin`). A vanished pin is a typed `TabNotFound` — never a silent retarget. Several agents share the one pin by naming their tab on each MCP call; separate cookies and storage need headless `--context`.
- **Frame scope** is per tab (`frameScopes` in `storage.session`, headless one `active_frame_<context>_<tab>` record each): `pinTab` restores the tab's own scope, `setActiveFrameId` writes the pinned tab's, a cross-document navigation of the pinned tab clears it, and a closed tab's is dropped.
- **Commands are serialized**: one global promise queue executes commands in arrival order, because the worker's state (pin, frame, commit watches) is one set of globals — concurrency would interleave it across commands. Health checks (`Status`, `Ping`) and request-scoped `WaitCancel` bypass the queue: a health check must not report dead because the worker is busy.
- **Click-opened tabs** are correlated by two signals (first wins): `tabs.onCreated`'s `openerTabId`, and `webNavigation.onCreatedNavigationTarget`'s `sourceTabId` — the latter covers `rel=noopener` popups, which deliberately carry no opener.
- **Navigation** settles through `waitNavigationSettled`, mirroring headless `navigation_settled`: committed (a main-frame commit event — `onCommitted` / `onHistoryStateUpdated` / `onReferenceFragmentUpdated` — or the URL leaving its pre-navigation value) AND parsed (readyState past `loading`), with the probe **bound to the committed document** via the commit's `documentId` (the headless loaderId equivalent — a same-URL reload can't settle on the old document). Deadline-bounded, no fixed sleeps, no debugger. History nav runs `history.back()/forward()` in the page (`chrome.tabs.goBack` refuses even with history in headless Chrome — measured); traversal is validated by commit events; a traversal that never commits becomes `NavigationFailed`.
- **Screenshots** are CDP `Page.captureScreenshot`, never `chrome.tabs.captureVisibleTab` (why: `capture.js`), and fail loud with typed errors except through `screenshot_error`. An action's `--capture` snapshots the tab the agent acts on next — a navigated document once parsed, an adopted popup once it has left `about:blank` — and a failed capture becomes `capture_error`, never a failed action, since a retry would re-run the side effect.
- **`tab switch`** activates the target within its own window and re-pins it, never raising the window to the OS foreground, which would take the user's focus from another app; every command reaches the tab through CDP whichever window is frontmost. Switching to the agent's own pinned tab changes nothing, so an MCP call naming its tab leaves the user's view alone.
- **Eval** is one debugger-routed contract for every frame (`cdpEval`): the form is decided by compiling (`Runtime.compileScript`), never by executing and retrying, and debugger evaluation ignores page CSP — headless parity, locked by the `/csp` fixture in both suites. `resolveFrameWorld` finds a frame's world by a one-shot nonce stamped into it, never by URL, and every evaluation targets its `uniqueContextId`; `"ISOLATED"` finds the content-script world for the `upload` and `click` object handoff. A frame `webNavigation` places in another process (a cross-site iframe) is reached through the child sessions the tab's debugger attaches: the resolved world carries its `sessionId`, and a click adds the `<iframe>` boundaries (`frameBoundaries`) — the headless `frames.rs` twin. `frame find` predicates ride the same path; frame *name* reads are precompiled `() => window.name` injections.
- **`hover`** is a native CDP `Input.dispatchMouseEvent` move in both modes (the bridge only resolves the element centre): a synthetic `mouseover` fires JS listeners but never the browser's internal `:hover` state.
- **`key_press`** is a native CDP `Input.dispatchKeyEvent` in both modes, never a synthetic `KeyboardEvent`, so Tab, Backspace, arrows and Enter (which submits a form, and so flows through the navigation watch) act as a keyboard's do; which key fields it sends: the comment in `action.js` / `action.rs`. Keys land on whatever holds browser focus, a focused element in a switched iframe included; switching a frame does not focus it.
